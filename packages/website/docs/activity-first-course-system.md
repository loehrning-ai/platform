# Activity-first course system

The course reader is a reference surface inside an operating environment. It is not the product's
only learning action. Every canonical lesson exposes a bounded decision mission, and every course
also exposes a separate applied project in a course-specific instrument. These activities do not
change the existing lesson-completion or assessment rules.

## Cognitive contract

Each lesson mission follows the same seven-signal sequence. It is separate from the five-stage applied
project ladder (`GROUND → BUILD → RUN → VERIFY → TRANSFER`):

| Phase      | Learner action                                                                                                                                                                                                                           | System evidence                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Predict    | Commit a prediction or classification before revealing the decisive signal                                                                                                                                                               | Bounded choice ID                                           |
| Manipulate | Open the course instrument and change one bounded control                                                                                                                                                                                | Local interaction signal                                    |
| Run        | Execute the bounded instrument action and receive a real provider/Sandbox receipt, an explicitly local synthetic case-evaluation receipt, or a visibly local prompt-structure learning receipt when the provider boundary is unavailable | Fixed learning receipt with its proof class                 |
| Inspect    | Identify the decisive claim, diff, lineage edge, metric, or missing control                                                                                                                                                              | Evidence selection                                          |
| Revise     | Choose the correction that follows from the inspected evidence and recalled rule                                                                                                                                                         | Bounded revision response                                   |
| Retrieve   | Reconstruct the governing rule after reference material is hidden                                                                                                                                                                        | Session-only written recall plus bounded retrieval response |
| Transfer   | Apply the rule to a different synthetic case                                                                                                                                                                                             | Transfer decision and rationale class                       |

Completing a lesson mission can advance the separate applied-project ladder. It is not required to
mark the ordinary lesson complete, unlock the ordinary final assessment, or earn a completion record.

The sequence combines four established learning-design findings:

- ICAP distinguishes passive exposure from active manipulation, constructive production, and genuine
  interaction. A button press is not automatically constructive activity.
- Productive-failure designs ask learners to generate and compare approaches before direct
  instruction, then make the canonical explanation available for contrast.
- Worked examples reduce unnecessary search for novices; support must fade toward independent
  execution instead of keeping every task fully open from the first minute.
- Retrieval practice requires producing an answer from memory. Rereading, highlighting, and revealing
  a flashcard before committing an answer do not satisfy that condition.

Primary references:

- Chi and Wylie, ICAP framework: <https://doi.org/10.1080/00461520.2014.965823>
- Karpicke and Blunt, retrieval practice: <https://doi.org/10.1126/science.1199327>
- Kapur, productive failure: <https://doi.org/10.1080/07370000802212669>
- Sweller and Cooper, worked examples: <https://doi.org/10.1207/s1532690xci0201_3>

## Layout contract

- Course navigation is independently scrollable and collapsible at desktop sizes and a focus-trapped
  drawer below the desktop breakpoint.
- The activity workspace supports docked and stacked layouts, a collapsed brief, keyboard and pointer
  resizing, and a true viewport-filling mode with Escape exit and focus restoration.
- Reading prose retains a bounded line length. Workspaces, diagrams, traces, tables, and editors use the
  available stage width up to the large-screen cap.
- Every structural panel can collapse without hiding the current state or leaving background content
  inert. Layout choices persist without encoding learner content.
- No document-level horizontal overflow is acceptable at 320, 390, 768, 1024, 1440, or 1728 pixels.

## Execution truth boundary

Three visibly different states are required:

1. `LOCAL` — deterministic browser manipulation against synthetic fixtures. It is labeled local and
   never described as a provider, shell, database, or notebook kernel. For prompt courses, a bounded
   local structure check can satisfy the lesson's learning-only Run signal after policy, access,
   quota, provider, or network failure. It produces no model output and cannot verify the applied
   project or certificate evidence.
2. `ISOLATED` — a server-created sandbox executes bounded work and returns actual stdout, stderr, exit
   code, files, diff, or data-course metric attestation. Its image is an explicitly reviewed immutable
   OCI digest; mutable tags fail closed. Network egress is denied before execution. Data workspaces
   accept fixed fixture programs and exact command sequences rather than learner SQL. The sandbox is
   stopped in a `finally` boundary.
3. `PROVIDER` — a server-held, allowlisted model receives an authenticated, rate-limited request under
   explicit DPA and retention readiness. The application reserves token quotas, not currency or
   provider spend. Provider failure never produces fabricated output. AI-Native and AI-Native
   Operator each request one model completion; their local controls do not execute tools, agents, or
   a workflow.

API keys never enter browser fields, synchronized learning progress, URLs, logs, or sandbox files.
Provider selection is a release-controlled allowlist. A promotional token balance is not a durable
product entitlement.

## Progress and privacy

- Applied-project evidence is derived from the exact canonical exercise record and engine kind. The
  browser validates its bounded schema before writing ordinary learning progress. That record is not
  a server signature or cryptographic attestation, even when the current session used a real provider
  or Sandbox response.
- Learning-only local prompt receipts and provider/Sandbox execution receipts are distinct fixed
  identifiers. Only the latter can satisfy final applied-project verification.
- The historical AI-Native `capstoneSubmitted` boolean remains a legacy certificate path and is not
  relabeled as proof that the new artifact exists.
- The new applied project is additional learning evidence. It is not an alternative to a required
  workshop quiz and does not gate ordinary course completion or certificate eligibility.
- Only fixed choices, booleans, numeric parameters, and bounded diagnostics enter synchronized
  progress. Free-form prompts, code, context, notes, outputs, and provider errors remain session-local
  unless a separate consented artifact-storage product is designed.
- Opening a workspace, watching playback, or pressing a navigation shortcut cannot award applied-work
  completion.

## Acceptance gates

1. Every canonical course mounts the shared shell and course-specific workspace in both locales.
2. Every lesson exposes a predict/manipulate/run/inspect/revise/retrieve/transfer path; imported widget count
   alone is insufficient.
3. Each engine has a behavior test that drives failure, correction, and successful verification.
4. Isolated/runtime routes prove authentication, durable user and IP quotas, bounded input/output,
   provider readiness, denied egress, timeout, teardown, and log privacy without a live credential.
5. Browser tests drive desktop collapse and resizing, full-screen entry/exit, mobile drawer and engine
   use, axe scans, console/page errors, and document overflow.
6. Authenticated foundation routes require a signed local fixture or authenticated-live proof before
   their browser behavior can be certified. Redirect-only tests are not equivalent.
