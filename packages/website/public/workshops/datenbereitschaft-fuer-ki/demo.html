      Behind the answer
      
  
      How the AI finds the right answer
      
  
      Four layers. The Skill guides. The semantic layer defines. The approved view serves. The grant enforces. Step through them.
      
  
      We follow one question through all four layers: logo churn. Pick "Logo churn" above to see the same question fail on raw tables (ERROR 42703).

      Part 1 · arrives
      A manager asks a plain question.
      It sounds simple. But "churn" can mean accounts or money. "Last quarter" needs a clock. The AI has to decide what each word means.
      Evaluation clock from the course: 2026-07-01T09:00:00Z
      
        
      incoming question
      What was logo churn rate by customer segment in the last complete quarter?-- open questions the AI must settle:-- which number? which rows? which months? which table?
      
      
      
      
      
      
        
      Part 2 · guides
      The Claude Skill switches on.
      The question names "logo churn rate", so the Skill matches. It tells the AI how to work: which metric file to read, which views to use, and what to refuse.
      It is guidance. It does not lock anything.
      claude/skills/foldline-analytics/SKILL.md
      
        
      SKILL.md (abbreviated)
      ---name: foldline-analyticsdescription: Answer FOLDLINE questions about ending MRR,  net new MRR, MRR movements, logo churn rate, ...  from the five approved analytics views, with a metric trace.---This Skill guides. It does not lock anything....3. Pick the metric in `references/metrics.md`.   Use only the view and column it names.4. Write one `SELECT` with schema-qualified names.5. ... Recompute rates and averages from their counts.6. End with a Trace.
      
      
      
      
      
      
        
      Part 3 · defines
      The semantic layer writes down the meaning.
      One file says what "logo churn rate" is: a ratio, counted in accounts, with a fixed base and one approved view. People, tests and Claude all read the same file.
      No guessing about columns.
      semantic/metric.yml
      
        
      metric.yml (abbreviated)
      - name: logo_churn_rate  label: Logo churn rate  type: ratio  relation: analytics.logo_churn_by_segment_quarter  numerator: churned_accounts  denominator: starting_accounts  result_grain: one row per customer_segment per quarter  population: >-    Accounts active at the end of the month before period_start.  zero_denominator: "null"  additivity:    class: non-additive  owner: revenue_analytics  version: 1.0.0
      
      
      
      
      
      
        
      Part 4 · serves
      The approved view hands over one tested number.
      The AI writes one plain SELECT on the view the definition names. The hard work (base, churn, rate) is already done and tested inside the view.
      segmentchurned / startrate %
      Enterprise4 / 4010.0
      Mid-Market4 / 4010.0
      SMB4 / 4010.0
      
        
      captured query, role foldline_ready_reader
      SELECT  lcsq.customer_segment,  lcsq.starting_accounts,  lcsq.churned_accounts,  lcsq.logo_churn_rate_pctFROM analytics.logo_churn_by_segment_quarter AS lcsqWHERE lcsq.period_start = DATE '2026-04-01'  AND lcsq.period_end_exclusive = DATE '2026-07-01'ORDER BY lcsq.customer_segment-- 3 rows: 4 of 40 = 10.0 % in each segment
      
      
      
      
      
      
        
      Part 5 · enforces
      The database grant is the lock.
      What if the AI ignores the guidance and reaches for customer names? The login has a database permission (grant) for five views and nothing else. The database says no.
      This is the only layer that cannot be talked around.
      Skill rule: "If a query is denied with SQLSTATE 42501, report the denial. Do not look for another route."
      
        
      captured attempt, role foldline_ready_reader
      SELECT account_name, contact_email FROM core.accounts LIMIT 1-- PostgreSQL answered:ERROR 42501: permission denied for schema core

      What made the difference
      
    
      
      
        
        
      1. GuideCLAUDE.md and the Skill tell the AI which metric file and views to use. Helpful, not a lock.
        2. 
        
      2. DefineThe semantic layer says which view and column answer "ending MRR", and that month-ends are never added up.
        3. 
        
      3. ServeFive approved views built for serving. Complete months only. Duplicates removed before they reach a number.
        4. 
        
      4. EnforceThe reader login can only select from the approved views. Everything else is denied by PostgreSQL.
        5. 
      
      
      
      Tests Database checks hold the expected numbers. They test the database and the course rules, not the AI.
      
      
      Instructions guide. The semantic layer defines. Approved views serve. Grants enforce.
