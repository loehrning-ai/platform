Reading the results: PASS means this setup handled that fixed case correctly. FAIL means a choice needs repair. NOT RUN means your test set did not include it. The run hash is an ID for these choices and results, not an AI confidence score. The freshness rule warns after 36 hours; it does not automatically block an answer.

The detail below is optional. These ten checks explain the five choices. “Proven” unlocks only when a matching test passes. A note by itself cannot make a failing check pass.

1

Restricted Surface

Minimize reach. Make forbidden reads fail.

R1 · Catalog boundary

One named read-only identity can select only the approved serving models.

R2 · Hard denial

A fixed test proves raw tables and direct identifiers are denied by PostgreSQL.

2

Explicit Structure

Declare grain, keys, clocks, and joins.

E1 · Grain contract

Every exposed model declares one-row-per grain, a stable key, and time semantics.

E2 · Structural validation

Business names, types, allowed values, and relationships are machine-readable and validated.

3

Agreed Meaning

Version the business contract. Consume it.

A1 · Metric contract

Formula, population, period, status, unit, dimensions, owner, and limits are explicit.

A2 · Runtime consumption

The application compiles and uses the contract; YAML is not inert documentation.

4

Dependable Data

Expose state. Define failure behavior.

D1 · Observable state

Freshness, quality, lineage, version, and ownership appear in the answer trace.

D2 · Failure path

A test proves stale or broken data warns or blocks according to policy.

5

Yardstick

Test answers, clarifications, refusals, and denials.

Y1 · Ground truth

Fixed questions carry reviewed values, periods, units, allowed assets, and trace requirements.

Y2 · Regression

Answer, clarify, refuse, permission-denial, and trace cases re-run after every relevant change.
