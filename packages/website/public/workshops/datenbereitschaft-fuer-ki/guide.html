1. The question

FOLDLINE is a made-up subscription software company. Monthly recurring revenue (MRR) is the value of its recurring subscriptions in a month. The course asks one question:

The one question

“Show ending MRR by month for the last complete quarter.”

The last complete quarter is Q2 2026: April, May and June.

2. The wrong answer and why

Given seven export tables, the AI answers with a tidy, plausible table:

April−€19,960
May€9,775
June€42,565

It added up each month's change and called it the ending level. Would you accept it? Decide before you open the explanation.

Reveal the explanationShowHide

Think of a bathtub. The level is the water in the tub at one moment; the change is what flowed in or out during a minute. The final level already includes every change.

Ending MRR is a level: the balance on the month's last day. The AI summed the monthly changes instead. April's negative value was the giveaway: a tub cannot hold minus 19,960 litres.

The arithmetic was fine. Nothing in the export tables said which column was a level and which a change.

3. The fix

Same question, same data, four changed parts:

  1. Approved views

    The AI reads a few approved database views instead of raw export tables.

  2. A written definition (semantic layer)

    A machine-readable definition of each business number: table, column, how to add it up and what never to do. Ending MRR is a month-end balance, never summed across months.

  3. Read-only access

    The AI's database user can read the approved views and nothing else; other reads fail with permission denied.

  4. Tests

    Fixed checks with known answers confirm the views, the definition and the grants.

A prompt can only ask the AI not to read a table. Only a database permission can block the read.

Asked again, the answer matches the database:

April€334,675
May€344,450
June€387,015

4. Honest limits

  • It should ask back when a question is vague, such as “How much MRR do we have?”
  • It should refuse questions the approved views do not support and data it must not see.
  • It should warn when the data are older than 36 h.
  • 9 of 9 tests passed. They check the database and course rules, not the AI.
  • The recorded runs cited the definition 0 of 3. A correct number does not show the AI used it.

Verdict: limited pilot, not signed off. The recorded runs are observations from August 2026, and the four parts changed together, so the comparison cannot isolate one. Use invented examples only; never paste employer data, personal records or credentials.

5. Your turn: five boxes

  1. 1. One question

    Say exactly what you want to know, with period and unit. “Show ending MRR by month for Q2 2026” beats “How much revenue?”

  2. 2. One approved view

    Choose the table or saved database query the AI may read.

  3. 3. Four blanks + who counts

    Kind of number (balance or change), rows per what, which months, which approved table. Together they make a vague question a shared definition.

    Then write who is in and who is out. Most real questions hide their trap here: “active members” may or may not include paused or trial members.

  4. 4. One boundary

    Name what must be refused and what the database must block.

  5. 5. One test

    Write one question with its time boundary and the result or behavior you expect.

    Name the source of the true value, for example last month's board report or a finance-approved figure.

Finish with one sentence: “For this question, using this approved data and this definition, we tested these boundaries; the next unknown is this one.”

6. Try it in Claude

Repeat the experiment in about 10 minutes with a Claude account and synthetic data.

  1. Set up Chat A: export tables

    Start a fresh chat outside any Project. Attach two files and add nothing else:

    monthly_revenue.csv · customer_master.csv

  2. Set up Project B: approved view + definition

    Create a Claude Project. Paste PROJECT-INSTRUCTIONS.txt into the project instructions. Add mrr_summary_monthly.csv, data_status_by_view.csv and metric-definitions.md to the project knowledge. Open a new chat inside it.

  3. Ask both the same question

    Today is 1 July 2026. Show ending MRR by month for the last complete quarter.

    If Claude asks back, reply: “Answer directly with your best interpretation.”

What to expect

Chat A most likely shows running totals labelled ending MRR:

April75,890
May85,665
June128,230

Plausible and wrong; a caveat about the missing opening balance usually hides in the small print.

Project B should match the database, with a trace naming the metric, source and data age:

April334,675
May344,450
June387,015

One live run is an observation. Upload only synthetic files.

Builder guide for data teams

Glossary

All 22 termsShowHide
MRR
Monthly recurring revenue: recurring subscription value for one month, not profit.
Table
Rows and columns holding data, like a structured spreadsheet.
View
A saved database query that looks like a table, exposing an approved subset with useful names.
Relation
The database's general word for anything shaped like a table, including tables and views.
Schema
A named folder inside a database that groups tables and views, for example analytics or core.
Serving model
The approved view an AI or report reads its answer from, instead of the raw tables.
Grain
What one row stands for. One customer per month and one whole month are different grains.
Snapshot
A value at one moment, like a month-end balance. Snapshots are not added up across months.
Non-additive
A number that must not be summed across time or groups. Month-end balances are non-additive across months.
SQL
The language used to ask a database for records or calculations.
Contract
An explicit agreement about a field or metric: meaning, unit, formula, owner and rules. It has an effect only where a system enforces it.
Semantic layer
The machine-readable definition of your business numbers: table, column, how to add it up and what never to do. Tools and AI read it instead of guessing from column names.
Identity
The database user or role a request runs as. Permissions are granted to an identity.
Least privilege
Only the permissions needed for the declared task. Read-only access can still expose too much.
SQLSTATE
A five-character error code from the database. 42501 means permission denied: the grant blocked the read.
Freshness
How old the data are and whether that age is acceptable for the decision.
Evaluation clock
The fixed “now” a test uses to judge freshness, so it gives the same result tomorrow.
Lineage
The path from a source through transformations to the answer.
Trace
The record of what one answer used: metric and version, period, source, data age and limitations.
Fixture
Fixed practice data that a test always runs against, so results can be compared.
Semantic checksum
A fingerprint of the definitions a run used. When they change, old results no longer count.
Run record
The record of one AI run: question, SQL, result and checks. The deck's appendix shows the historical records.
