One question, one fictional company, five rules. Learn why a convincing AI answer can be wrong and how to make one particular question safer to answer.

Start with a separate warm-up example

Your subscription business ends April with 100 euros in monthly recurring revenue. The increase during April was 20 euros.

An AI adds both numbers and reports 120 euros at month end.

Would you accept it? Say why before opening the explanation.

Reveal the explanation

The correct month-end balance is 100 euros. It already includes the 20-euro increase. The AI can add perfectly and still count the wrong things.

Think of a bathtub: the water level at the end already includes the water added during the minute. Level is what exists at one moment. Change is what moved during a period.

In the main FOLDLINE case, the mistake is different: monthly changes are presented as ending balances. Both mistakes come from confusing a level with a change.

Your route through the course

  1. Meet FOLDLINE. It is a made-up subscription software company. Monthly recurring revenue (MRR) means the value of recurring subscriptions for a month; it is not profit.
  2. Vote on the first answer. Notice how easy it is to trust a tidy chart. The problem is hidden in what the fields mean.
  3. Repair the data interface. Keep the question and data fixed. Add approved analytical views, definitions, context and access boundaries together.
  4. Test awkward questions too. A useful system sometimes asks for clarification, refuses an unsupported question or blocks forbidden access.
  5. Fill the five boxes below. Explain what is known and what must still be tested. The 75-minute course is followed by 15 minutes of questions.
  6. Optional follow-up: run the separate 12-minute browser lab after the session.

The slides are designed for a large landscape screen. Use the arrow keys to reveal one step at a time. Press P from the deck for speaker notes and controls; Esc returns from an appendix. This guide and the browser lab also work on a phone.

The five boxes you must fill

  1. 1. One question

    State exactly what you want to know, including time period and unit. “Show ending MRR by month for Q2 2026” is clearer than “How much revenue?”

  2. 2. One approved view

    Choose the table or saved database query the AI may read.

  3. 3. Four blanks

    What kind of number: a balance or a change? One row per what? Which months? Which approved table? These blanks turn an ambiguous question into a shared definition.

  4. 4. One boundary

    Specify what must be refused and what the database must block. “Please do not read this” is an instruction; permission denied is an enforced limit.

  5. 5. One test

    Write one question and the result or behavior you expect. Include its time boundary. Record what you actually tested and the next unknown.

Optional follow-up: the 12-minute lab

In a group, one person operates, one records the evidence, and one challenges it. Working alone, take all three roles.

  1. Minutes 0 to 2: Open the lab. Read the fixed question and synthetic-data boundary.
  2. Minutes 2 to 5: Set five choices: data surface, metric behavior, permissions, freshness and yardstick. “Yardstick” means the set of checks used to judge the result.
  3. Minutes 5 to 8: Press Test My Choices. Defaults are deliberately weak. A check you did not run is missing evidence, even if the first answer looks right.
  4. Minutes 8 to 10: Repair one choice and run again. Notice that a change invalidates the old results.
  5. Minutes 10 to 12: Copy or print the receipt. State the first weak control and one next test.
Stuck? Show the repair hints

Choose Approved MRR summary, Month-end balance, Refuse + restrict access, Warn after 36 hours and All six cases. The ending balance is a snapshot, not the sum of monthly movements. This lab's freshness rule warns after 36 hours; it does not impose a hard expiry.

“Proven” in this lab means its fixed synthetic checks passed. It says nothing about your employer's systems.

Words without the fog

MRR
Monthly recurring revenue: recurring subscription value for one month, not profit.
Table
Rows and columns holding data, like a structured spreadsheet.
View
A saved database query presented like a table. It can expose an approved subset and useful names.
Grain
What one row stands for. One customer per month and one whole month are different grains.
SQL
The language used to ask a database for records or calculations.
Contract
An explicit agreement about a field or metric: meaning, unit, formula, owner and rules. It only changes a system if that system actually uses it.
Least privilege
Only the permissions needed for the declared task. Read-only access can still expose too much.
Freshness
How old the data are and whether that age is acceptable for the decision.
Lineage
The path from a source through transformations to the answer.

Know which evidence you are seeing

Recorded model answers: historical observations from August 2026, with direct answers forced for comparison. They do not show the tool's default behavior. The underlying model version was not recorded. One successful run is not proof that the next run will succeed.

Combined repair: views, definitions, context and permissions change together. The comparison does not isolate the effect of any single ingredient.

Fixed database checks: captured results for known synthetic cases. They are separate from model behavior.

Browser lab: a deterministic simulation. It does not call an AI, run SQL or enforce database permissions.

Use invented examples only. Do not paste employer data, personal records or credentials. The lab keeps only your selections locally. Custom text is not saved; exported receipts omit it. This course does not certify production readiness.

Finish with one sentence

“For this question, using this approved data and this definition, we tested these boundaries; the next unknown is this one.”

If that sentence is still vague, your next job is to clarify it.
