Using AI to understand business reports

Build an AI analyst for one real decision.

This is a build, not a talk. In seven steps you'll turn a company's raw month into a metrics summary, a dashboard, and one board-level call — entirely in the Claude app, on your subscription. No code. No API key. First, two ideas that make the whole thing possible.

Concept · the two worlds

Claude is the brain. The tools are just templates.

The confusion to clear up first: you do not need an API key. Everything runs on your Claude subscription — because the intelligence is Claude, and the "generator tools" are only formats Claude fills in.

Claude = the brain (your subscription)

  • Projects — the company brain (context)
  • Skills — your metric definitions
  • Connectors — live data (Drive, email)
  • Claude Code — reads files, runs the work

No API key. No separate service.

The tools = templates Claude fills

The report and dashboard generators have a nice format. We reuse the format and let Claude populate it — we never run their built-in AI (that's the part that would need a key).

  • report format → Claude drafts the report
  • dashboard template → Claude fills the numbers

Free to clone if you want the "productized" version.

The case · NORDA Werke (synthetic)

One company, one month, one call.

NORDA Werke — an Augsburg electronics maker, September 2023. It's month-end and the numbers don't obviously agree.

CRAFT (premium kitchen) earns the second-most revenue on the least volume, at the highest prices — and carries the most quality defects. The decision: rework the line, or reallocate its marketing budget for Q3? And a lesson baked in: some things (true margin, customer returns per line) the data simply can't answer.

Step 1 · ground it

Get the data.

Open the kit folder. Five plain CSVs (Excel-openable) + a one-page company backstory — this month's raw material.

Read data/company-backstory.md and both files in reports/. In two sentences, tell me who NORDA is and what decision this month's report is building toward.

What to expect: Claude learns the company and surfaces the CRAFT question. This is the "company brain" in miniature.

Step 2 · the story

Read the reports.

The kit ships two monthly reports (August + September) in a reusable format. Claude reads them for the narrative behind the numbers — and you'll see how a report gets drafted into that same template each month.

  • reports/2023-09-monthly-report.md — the month under review
  • reports/2023-08-monthly-report.md — the prior month (for month-over-month)
  • reports/report-template.md — the format Claude drafts future months into

Step 3 · the key move

Build the metrics Skill.

A Skill encodes what the numbers mean here — and how to compute them the same way every time. This is what turns a one-off analysis into a repeatable system.

Use the norda-metrics skill to compute this month's numbers. Run its script, then show me: total revenue and units, revenue and defects by line, and the three things that matter most — following the skill's reading rules. Don't estimate any number the script can compute.

What to expect: Claude runs the skill's deterministic script → writes metrics.json → explains it. CRAFT is flagged: €4.1M on 9,162 units, the most defects. The arithmetic is exact — the model never guesses a number.

Step 4 · ground everything

The company brain.

In the desktop app you'd load the backstory + metric definitions + the report into a Project — so every future question is answered in NORDA's terms, not in general. The kit carries the same context in files so Claude Code reads it directly.

  • Context beats prompting — the same question gets sharper once Claude knows the company
  • Reusable — next month's chat starts already knowing what "margin" and "returns" mean here

Step 5 · live data

Connect it, don't copy-paste.

Claude Connectors let Claude pull the real file from where it already lives — Google Drive, email — still on your subscription, still no API key.

Connect to my Google Drive, find the latest NORDA monthly data file, bring it in, and run the norda-metrics skill on it.

Why it matters: next month is one message, not a re-upload. The analyst reaches the data itself.

Step 6 · the template, filled

Populate the dashboard.

This is "tools as templates" in action: Claude Code writes the computed numbers into the dashboard template and opens it. No install, no key — a real, shareable one-pager.

Populate the dashboard: write dashboard/data.js from metrics/metrics.json (as window.NORDA_DATA = …), then open dashboard/index.html so I can see it.

What to expect: the loehrning dashboard — revenue by line, defects by line (CRAFT highlighted), marketing, escalations, and "the call on the table."

Step 7 · the point of all of it

Make the call.

Not a summary — a decision, with the number behind it and the cost of being wrong.

Make the decision: should NORDA rework CRAFT or reallocate its marketing budget for Q3? Give the number that backs it, the cost of being wrong, and state clearly what this data can't tell us.

What to expect: a cited recommendation — and honesty about the limits (no true margin, defects ≠ customer returns). That is the whole workshop in one answer.

Before you trust it

Four watch-outs.

Invented numbers

Ask "show me the exact cell each number came from." No cite, no trust. (The skill's script removes this risk entirely for the metrics.)

Generic meaning

"Revenue up = good" ignores that CRAFT's price ≠ margin. Ground it in your definitions.

What data can't answer

True margin, customer returns per line — not in the data. A good analyst says so instead of faking it.

One-off effort

A brilliant analysis you can't reproduce next month. The Skill makes it repeat.
