Module 1 · Understand

Is this number a level or a change?

In one lineEnding MRR is the water level at month end, and net new MRR is what flowed in or out that month. 354,635 + 32,380 = 387,015.

Move through the months: the tub shows the level, the arrow the change and the ledger the sum.

Tub: ending MRR (level). Arrow: the change.

Ending MRR and net new MRR by month, EUR
MonthEnding MRR (level)Net new MRR (change)

Month: Dec 2025. Arrow keys work on the slider.

Ledger

    Good

    “Ending MRR, end of June: €387,015.” A level, read at one moment.

    Counter-example

    “Ending MRR, April: −€19,960.” The recorded AI run plotted April's change as the April level.

    Why it fails

    monthly_revenue.amount holds each month's change (new + expansion − contraction − churn), and ending MRR cannot be negative here.

    For builders SQL

    Serve the level beside the change and test the identity every month (case Q02). Never let an AI rebuild a level from a window of changes: in the rehearsal it summed the changes from January and left out the opening balance.

    -- Q02: previous level + change = level, for every month
SELECT month_start, ending_mrr_eur, net_new_mrr_eur,
       lag(ending_mrr_eur) OVER (ORDER BY month_start) + net_new_mrr_eur
         = ending_mrr_eur AS identity_holds
FROM analytics.mrr_summary_monthly
ORDER BY month_start;

    Module 2 · Understand

    Can I add these numbers?

    In one lineChanges add. Levels add across things, never across time. Rates never add: recompute them from their counts.

    Pick a card, then the tray it belongs in.

      Add along every axis.

        Add across things, never across time.

          Never add. Recompute from the parts.

            Average or pool?

            In a web shop, search converts 400 of 20,000 sessions (2 %) and email 8 % of its sessions. Move the email sessions and watch which number moves.

            Conversion rates

            FOLDLINE is right by luck: every segment started Q2 with 40 accounts, so the average of three 10.0 % rates equals the pooled 12 of 120. Drag email sessions to 20,000 and the average and pooled rates agree too: equal bases hide the bug.

            Good

            Q2 net new: −19,960 + 9,775 + 42,565 = 32,380. Logo churn: recompute 12 of 120 = 10.0 %.

            Counter-example

            334,675 + 344,450 + 387,015 = 1,066,140. Or churn over every customer row in one segment: 4 of 48 = 8.33 %.

            Why it fails

            Three month-end levels added describe nothing. The 48 includes 8 accounts that joined during Q2 and could never have left the starting base.

            For builders YAML

            Write the additivity class on every metric. A tool that reads across_time: none can refuse to sum the level.

            - slug: ending_mrr
  aggregation: snapshot         # a level
  additivity: {class: semi-additive, across_segments: sum, across_time: none, time_rollup: last_value}
- slug: net_new_mrr
  aggregation: movement         # a change
  additivity: {class: additive}
- slug: logo_churn_rate
  aggregation: ratio
  numerator: churned_accounts
  denominator: starting_accounts   # active at the start of the period (end of the month
                                   # before it starts): 40 per segment on 1 April
  zero_denominator: "null"         # 0/0 is no rate, never 0 %
  additivity: {class: non-additive, time_rollup: recompute_from_components}

            Module 3 · Understand

            What is a semantic layer, and where does it sit?

            In one lineA semantic layer sits between your tables and every reader and writes down what each number means, which view answers it and what to refuse. The four blanks are a tiny one.

            source

            Feeds exactly as received.

            source.billing_account_mrr

            core

            Renamed, typed, decoded, deduplicated. Identifiers stay here.

            core.account_months

            analytics

            Five approved views, one per question family.

            analytics.mrr_summary_monthly

            semantic files

            The written meaning.

            model.yml
            metric.yml
            policy.yml
            verified-questions.yml

            readers

            Each gets the same definition.

            What the AI has to work with

            What the selected reader receives

            Cited the definition: 0 of 3

            Fix: require the metric name and version in every answer's trace, and grade it.

            Good

            ending_mrr 1.0.0 is copied to the AI tool, the tests, the coding guide and the catalog, and every trace names it.

            Counter-example

            The export lane: seven tables and no written meaning. “Three of them sound like the answer.”

            Why it fails

            With nothing written down, the AI guessed all four blanks, picked monthly_revenue and labelled a change ending_mrr. A semantic layer only guides; the grants do the locking.

            For builders YAML

            The four blanks become four fields, named as on the deck's appendix slide “The full ending MRR contract”: aggregation, result_grain, time_behavior and model.

            - slug: ending_mrr
  model: analytics.mrr_summary_monthly   # Which table?
  aggregation: snapshot                  # Kind of number?
  result_grain: monthly                  # Rows per what?
  unit: EUR
  owner: revenue_analytics
  freshness_sla_hours: 36
  time_behavior:                         # Which months?
    period_rule: end_of_period           # each complete month-end; never sum
    default_period: last_complete_quarter
  limitations: [Never sum ending MRR across months.]
  contract_version: 1.0.0
  # block 2: the builder's extra fields
  ambiguous_terms: [mrr, revenue]        # ask back (C01)

            Where does one number come from?

            In one lineSource keeps the feeds, core makes them true and labelled, and analytics serves one plate per question. Each trap is fixed in one layer.

            source

            As received. Never renamed.

            core

            Rename, type, decode, deduplicate, then tables with keys.

            analytics

            Five views. The AI reads only here.

            Where is each trap fixed?

              Good

              The AI's login sees five views in analytics. April 334,675 traces to 144 rows in core.account_months and to the feed.

              Counter-example

              foldline_bad_reader sees all seven export tables in saas_bad.public.

              Why it fails

              The AI read the raw export tables. It picked monthly_revenue, whose sums are the true monthly changes, and read them as levels. The table needed a clear name and the level beside it.

              For builders SQL

              A lineage check you can run: a second person recomputes April from the feed instead of the view under test.

              -- analytics: what the AI reads
SELECT ending_mrr_eur FROM analytics.mrr_summary_monthly
WHERE month_start = DATE '2026-04-01';                 -- 334675.00
-- core: the account grain behind it
SELECT count(*), count(*) FILTER (WHERE ending_mrr_eur > 0), sum(ending_mrr_eur)
FROM core.account_months WHERE month_start = DATE '2026-04-01';  -- 144 | 123 | 334675.00
-- source: the feed, in cents, with a text period
SELECT sum(mrr_cents) / 100 FROM source.billing_account_mrr
WHERE period = '2026-04';                               -- 334675

              Module 5 · Design

              What would a stranger have to guess?

              In one lineA name travels with every query. Say shape, unit and time, put the grain in the view name, write codes as words, keep one key name and always name the schema.

              Pick a name from FOLDLINE's export lane.

              Good

              analytics.mrr_summary_monthly(month_start, ending_mrr_eur, net_new_mrr_eur). Level beside change, unit and grain in the names.

              Counter-example

              monthly_revenue(dt, segment, amount), and the recorded run's alias SUM(amount) AS ending_mrr.

              Why it fails

              amount says nothing about shape. The alias turned a guess into a label, and the deck's checklist counted “Column named ending_mrr” as a reason to trust it.

              For builders SQL

              A column comment holds shape, unit, grain and one “never”. Test Q06 checks that every view comment carries the definition version.

              COMMENT ON COLUMN analytics.mrr_summary_monthly.ending_mrr_eur IS
  'Level: recurring value active at the final instant of the month, EUR.
   Never sum across months; for a quarter return each month or the last month.';
-- Lint: every served column that uses a banned name
SELECT table_schema, table_name, column_name
FROM information_schema.columns
WHERE table_schema = 'analytics'
  AND column_name IN ('amount','value','total','dt','date','ts','seg','status','state','type','id','mrr');

                  Module 7 · Lock and connect
                  
    
                  Which gate actually stops a request?
                  
    
                  In one lineTwo locks: refuse early, enforce anyway. Instructions and Skills guide. A hook or a read-only default is a guardrail. Together they refuse early; only the database role enforces.
                  
    
                  
      
                  Pick a request
                  
      
                  
        
        
        
        
      
                  
      
                  
      
                  Pick a request and press Send.
                  
    
                  
    
                  
      
                  Good
                  The AI's login may read five approved views and nothing else: no writes, no scratch copies, no export database.
                  
      
                  Counter-example
                  “The prompt says don't read emails, and the login is read-only, so we're safe.”
                  
      
                  Why it fails
                  A prompt is advice, and read-only is a default the session can switch off with one command. On PostgreSQL 16 the reader could still create a scratch table, because a new database grants TEMP to PUBLIC until you revoke it.
                  
    
                  
    
                  For builders SQL
                  
      
                  foldline_ready_reader gets SELECT on five views, no TEMP, no CREATE, no CONNECT on saas_bad, and search_path = ''. BEGIN READ WRITE switches the read-only default off, and with TEMP left to PUBLIC the reader created a temp table on PostgreSQL 16 (case B-T01).
                  
      
                  The grants are an allowlist. Every line below is a lock except the last three, which are guardrails.
                  

                  REVOKE ALL ON DATABASE saas_ready FROM PUBLIC;       -- removes TEMP and CONNECT
REVOKE CONNECT ON DATABASE saas_bad FROM PUBLIC;
GRANT CONNECT ON DATABASE saas_ready TO foldline_ready_reader;
GRANT USAGE ON SCHEMA analytics TO foldline_ready_reader;
GRANT SELECT ON analytics.mrr_summary_monthly,
               analytics.logo_churn_by_segment_quarter,
               analytics.expansion_mrr_by_country_monthly,
               analytics.account_mrr_monthly,
               analytics.data_status_by_view TO foldline_ready_reader;
-- guardrails: defaults the reader can change, not locks
ALTER ROLE foldline_ready_reader SET default_transaction_read_only = on;
ALTER ROLE foldline_ready_reader SET statement_timeout = '5s';
ALTER ROLE foldline_ready_reader SET search_path = '';
                  
      
                  Test as the login, not with SET ROLE: role settings load only at login.

                    Module 9 · Lock and connect
                    
    
                    How old may the data be?
                    
    
                    In one lineWarn after 36 hours and still answer. Block only on a written rule: an incomplete period or a failing quality check. Never invent an expiry.
                    
    
                    
      
      
      
                    
      
                    
      
                    
        
        
        
      
                    
      
                    
    
                    
    
                    
      
                    Good
                    At 60 hours: answer, state the load time (2026-07-01 06:00 UTC) and the age, and escalate to revenue_analytics.
                    
      
                    Counter-example
                    “Older than 48 hours: refuse.” Or a 60-hour snapshot returned with no warning.
                    
      
                    Why it fails
                    Nobody wrote or approved a 48-hour rule, so the next run can behave differently and no test can be written. Hiding the age passes a 60-hour-old snapshot off as fresh.
                    
    
                    
    
                    For builders SQL
                    
      
                    The view stores facts; the caller supplies the clock. No now() in a view, so F00 and F01 can run on frozen clocks.
                    

                    SELECT view_name, warn_after_hours, hard_expiry_hours,   -- 36, NULL
       extract(epoch FROM (TIMESTAMPTZ '2026-07-01 09:00:00+00'
                           - data_loaded_at_utc)) / 3600 AS age_hours   -- 3
FROM analytics.data_status_by_view
WHERE view_name = 'analytics.mrr_summary_monthly';

                            Reference · Words
                            
    
                            Glossary
                            
    
                            
      
                            MRR
                            Monthly recurring revenue: what accounts pay per month for subscriptions. It is not accounting revenue, cash or profit.
                            
      
                            Level, change, rate
                            A level is measured at one moment (ending MRR), a change flows in or out during a period (net new MRR), and a rate divides one count by another (logo churn, 4 of 40 = 10.0 %).
                            
      
                            Four blanks
                            What the AI had to guess in the workshop: kind of number, rows per what, which months, which table.
                            
      
                            Five boxes
                            The workshop's question card: question, approved view, four blanks, boundary (what must be refused) and test.
                            
      
                            Schema
                            A named folder of tables and views in a database. FOLDLINE has source, core and analytics; the AI may look only in analytics.
                            
      
                            View
                            A saved query that looks like a table and computes its rows from core each time it is read, such as analytics.mrr_summary_monthly.
                            
      
                            Login and role
                            A role is a database user, and a role that may connect is a login. FOLDLINE's AI connects as foldline_ready_reader.
                            
      
                            Grant
                            A permission given to a role. Anything not granted fails with SQLSTATE 42501, “permission denied”.
                            
      
                            Trace
                            The end of an answer that names metric and version, view or file, period, unit, load time and data age.
                            
      
                            Pooled rate
                            Total numerator ÷ total denominator, for example 12 of 120 = 10.0 % churn across segments.
                            
      
                            Pseudonymous key
                            A stable stand-in for an identity, such as fl_0006. It can be joined back to a person or company, so it is not anonymous.
                            
      
                            Guardrail
                            A check or default the reader can bypass, such as a hook, a read-only default or a connector setting.
                            
      
                            Additive, semi-additive, non-additive
                            Changes add along every axis. Levels add across things, never across time. Rates, averages and distinct counts never add; recompute them from their parts.
                            
      
                            Serving view
                            A view in analytics cut to one question family, with approved names, units, data-state columns and complete periods only.
                            
      
                            Allowlist
                            A list of what is allowed, with everything else denied: the reader may SELECT five named views. A denylist lets a new schema through the day it appears.
                            
      
                            MCP
                            Model Context Protocol, a standard way to connect an AI tool to a data source. An MCP database connector logs in with whatever login you give it, so give it the read-only reader.
                            
      
                            Skill
                            A folder with a SKILL.md that Claude loads when its description matches the task, such as .claude/skills/foldline-analytics/SKILL.md.
                            
      
                            Hook
                            A command Claude Code runs at a fixed point, such as before a tool call. It is a guardrail: it can block a query outside the allowlist.
                            
      
                            Evaluation clock
