Module 1 · Understand

Is this number a level or a change?

Say it in one lineEnding MRR is the water level at month end. Net new MRR is the water that flowed in or out during the month. 354,635 + 32,380 = 387,015.

Move through the months. The tub shows the level. The arrow shows the change. The ledger writes the sum.

Tub: ending MRR (level). Arrow: the change.

Ending MRR and net new MRR by month, EUR
MonthEnding MRR (level)Net new MRR (change)

Month: Dec 2025. Use the arrows or the slider; arrow keys work on the slider.

Ledger

    Good

    “Ending MRR, end of June: €387,015.” A level, read at one moment.

    Counter-example

    “Ending MRR, April: −€19,960.” The recorded AI run plotted April's change as the April level.

    Why it fails

    monthly_revenue.amount holds each month's change: new + expansion − contraction − churn. Ending MRR cannot be negative here. Right answer to a different question.

    For builders SQL

    Serve the level and the change side by side, and test the identity every month (case Q02). Never ask an AI to rebuild a level from a window of changes: the dry run did exactly that and started the tub empty.

    -- Q02: previous level + change = level, for every month
SELECT month_start, ending_mrr_eur, net_new_mrr_eur,
       lag(ending_mrr_eur) OVER (ORDER BY month_start) + net_new_mrr_eur
         = ending_mrr_eur AS identity_holds
FROM analytics.mrr_summary_monthly
ORDER BY month_start;

    Module 2 · Understand

    Can I add these numbers?

    Say it in one lineChanges add. Levels add across things, never across time. Rates never add: recompute them from their counts.

    Pick a card, then pick the tray it belongs in. Each placement shows the number that proves it.

      Add along every axis.

        Add across things, never across time.

          Never add. Recompute from the parts.

            Average or pool?

            A web shop has two channels. Search converts 400 of 20,000 sessions (2 %). Email converts 8 % of its sessions. Move the email sessions and watch which number moves.

            Conversion rates

            FOLDLINE is right by luck: every segment started Q2 with 40 accounts, so the average of three 10.0 % rates equals the pooled 12 of 120. Drag the email sessions to 20,000 and the two methods agree here too. Equal bases hide the bug.

            Good

            Q2 net new: −19,960 + 9,775 + 42,565 = 32,380. Logo churn: recompute 12 of 120 = 10.0 %.

            Counter-example

            334,675 + 344,450 + 387,015 = 1,066,140. Or churn over every customer row in one segment: 4 of 48 = 8.33 %.

            Why it fails

            Three month-end levels added describe nothing. The 48 includes 8 accounts that joined during Q2 and could never have left the starting base.

            For builders YAML

            Write the additivity class on every metric. A tool that reads across_time: none can refuse to sum the level.

            - slug: ending_mrr
  aggregation: snapshot         # a level
  additivity: {class: semi-additive, across_segments: sum, across_time: none, time_rollup: last_value}
- slug: net_new_mrr
  aggregation: movement         # a change
  additivity: {class: additive}
- slug: logo_churn_rate
  aggregation: ratio
  numerator: churned_accounts
  denominator: starting_accounts   # active at the start of the period (end of the month
                                   # before it starts): 40 per segment on 1 April
  zero_denominator: "null"         # 0/0 is no rate, never 0 %
  additivity: {class: non-additive, time_rollup: recompute_from_components}

            Module 3 · Understand

            What is a semantic layer, and where does it sit?

            Say it in one lineA semantic layer is the written layer between your tables and every reader. It says what each number means, which view answers it and what must be refused. The four blanks are a tiny one.

            source

            Feeds exactly as received.

            source.billing_account_mrr

            core

            Renamed, typed, decoded, deduplicated. Identifiers stay here.

            core.account_months

            analytics

            Five approved views, one per question family.

            analytics.mrr_summary_monthly

            semantic files

            The written meaning.

            model.yml
            metric.yml
            policy.yml
            verified-questions.yml

            readers

            One definition, four readers.

            What the AI has to work with

            What the selected reader receives

            Cited the definition: 0 of 3

            Loaded is not the same as used. Fix: require the metric name and version in every answer's trace, and grade it.

            Good

            One definition, ending_mrr version 1.0.0, copied to the AI tool, the tests, the coding guide and the catalog. Every answer's trace names it.

            Counter-example

            The export lane: seven tables and no written meaning. “Three of them sound like the answer.”

            Why it fails

            With nothing written down, the AI guessed all four blanks, picked monthly_revenue and labelled a change ending_mrr. A semantic layer guides; it cannot deny. The grants still lock.

            For builders YAML

            The four blanks become four fields, with the same keys as the deck's appendix slide “The full ending MRR contract”: aggregation, result_grain, time_behavior and model. Everything else in metric.yml keeps them checkable.

            - slug: ending_mrr
  model: analytics.mrr_summary_monthly   # Which table?
  aggregation: snapshot                  # Kind of number?
  result_grain: monthly                  # Rows per what?
  unit: EUR
  owner: revenue_analytics
  freshness_sla_hours: 36
  time_behavior:                         # Which months?
    period_rule: end_of_period           # each complete month-end; never sum
    default_period: last_complete_quarter
  limitations: [Never sum ending MRR across months.]
  contract_version: 1.0.0
  # block 2: the builder's extra fields
  ambiguous_terms: [mrr, revenue]        # ask back (C01)

            There is one numbered build order: the runbook in module 12. The semantic layer is built in these runbook steps: 0 question and owner; 1 the four blanks and the case list in verified-questions.yml; 2 truth rows, computed by two people; 6 model.yml and metric.yml; 8 policy.yml; 10 compile by hand to each reader; 9 and 11 test that the readers use it.

            Module 4 · Design

            Where does one number come from?

            Say it in one lineSource keeps the feeds, core makes them true and labelled, analytics serves one plate per question. Each trap is fixed in one layer. The export table was unlabelled, not wrong.

            source

            As received. Never renamed.

            core

            Rename, type, decode, deduplicate, then tables with keys.

            analytics

            Five views. The AI reads only here.

            Where is each trap fixed?

              Good

              The AI's login sees five views in analytics. April 334,675 traces to 144 rows in core.account_months and to the feed.

              Counter-example

              foldline_bad_reader sees all seven export tables in saas_bad.public.

              Why it fails

              The AI got the delivery boxes, not the plate. It picked monthly_revenue, whose sums are exactly the true monthly changes, and read them as levels. The fix is a name and a neighbour, not a different number.

              For builders SQL

              Lineage you can run. The second person recomputes April from the feed, not from the view under test.

              -- analytics: what the AI reads
SELECT ending_mrr_eur FROM analytics.mrr_summary_monthly
WHERE month_start = DATE '2026-04-01';                 -- 334675.00
-- core: the account grain behind it
SELECT count(*), count(*) FILTER (WHERE ending_mrr_eur > 0), sum(ending_mrr_eur)
FROM core.account_months WHERE month_start = DATE '2026-04-01';  -- 144 | 123 | 334675.00
-- source: the feed, in cents, with a text period
SELECT sum(mrr_cents) / 100 FROM source.billing_account_mrr
WHERE period = '2026-04';                               -- 334675

              Module 5 · Design

              What would a stranger have to guess?

              Say it in one lineA name is the only documentation that travels with every query. Say the shape, the unit and the time; put the grain in the view name; use words, not codes; one key name; always the schema.

              These are real column and table names from FOLDLINE's export lane. Pick one.

              Good

              analytics.mrr_summary_monthly(month_start, ending_mrr_eur, net_new_mrr_eur). Level and change side by side, unit in the name, grain in the view name.

              Counter-example

              monthly_revenue(dt, segment, amount), and the recorded run's alias SUM(amount) AS ending_mrr.

              Why it fails

              amount says nothing about shape. The alias turned a guess into a label, and the deck's checklist counted “Column named ending_mrr” as a reason to trust it.

              For builders SQL

              A comment is a name that can hold a sentence: shape, unit and grain, plus one “never”. Test Q06 checks that every view comment carries the definition version.

              COMMENT ON COLUMN analytics.mrr_summary_monthly.ending_mrr_eur IS
  'Level: recurring value active at the final instant of the month, EUR.
   Never sum across months; for a quarter return each month or the last month.';
-- Lint: every served column that uses a banned name
SELECT table_schema, table_name, column_name
FROM information_schema.columns
WHERE table_schema = 'analytics'
  AND column_name IN ('amount','value','total','dt','date','ts','seg','status','state','type','id','mrr');

                  Module 7 · Lock and connect
                  
    
                  Which gate actually stops a request?
                  
    
                  Say it in one lineTwo locks: refuse early, enforce anyway. Instructions and Skills guide; a hook and a read-only default are a guardrail; only the database role enforces. Guides and guardrails belong to the first lock (refuse early). Only the database role is the second lock (enforce anyway).
                  
    
                  
      
                  Pick a request
                  
      
                  
        
        
        
        
      
                  
      
                  
      
                  Pick a request and press Send.
                  
    
                  
    
                  
      
                  Good
                  The AI's login may read five approved views and nothing else. It cannot write, cannot make scratch copies, and cannot open the export database.
                  
      
                  Counter-example
                  “The prompt says don't read emails, and the login is read-only, so we're safe.”
                  
      
                  Why it fails
                  A prompt is advice. Read-only is a default the session can switch off with one command. On PostgreSQL 16 the reader could still create a scratch table, because every new database lets everyone do that until you revoke it.
                  
    
                  
    
                  For builders SQL
                  
      
                  In database terms: foldline_ready_reader gets SELECT on five views, no TEMP, no CREATE, no CONNECT on saas_bad, and search_path = ''. Read-only is a default: BEGIN READ WRITE switches it off. A new database grants TEMP to PUBLIC, so with TEMP left to PUBLIC the reader created a temp table on PostgreSQL 16 (case B-T01).
                  
      
                  An allowlist, not a denylist. Every line below is a lock except the last three, which are guardrails.
                  

                  REVOKE ALL ON DATABASE saas_ready FROM PUBLIC;       -- removes TEMP and CONNECT
REVOKE CONNECT ON DATABASE saas_bad FROM PUBLIC;
GRANT CONNECT ON DATABASE saas_ready TO foldline_ready_reader;
GRANT USAGE ON SCHEMA analytics TO foldline_ready_reader;
GRANT SELECT ON analytics.mrr_summary_monthly,
               analytics.logo_churn_by_segment_quarter,
               analytics.expansion_mrr_by_country_monthly,
               analytics.account_mrr_monthly,
               analytics.data_status_by_view TO foldline_ready_reader;
-- guardrails: defaults the reader can change, not locks
ALTER ROLE foldline_ready_reader SET default_transaction_read_only = on;
ALTER ROLE foldline_ready_reader SET statement_timeout = '5s';
ALTER ROLE foldline_ready_reader SET search_path = '';
                  
      
                  Test as the login, not with SET ROLE: role settings load only at login.

                    Module 9 · Lock and connect
                    
    
                    How old may the data be?
                    
    
                    Say it in one lineWarn after 36 hours and still answer. Block only on a written rule: an incomplete period or a failing quality check. Never invent an expiry.
                    
    
                    
      
      
      
                    
      
                    
      
                    
        
        
        
      
                    
      
                    
    
                    
    
                    
      
                    Good
                    At 60 hours: answer, state the load time (2026-07-01 06:00 UTC) and the age, and escalate to revenue_analytics.
                    
      
                    Counter-example
                    “Older than 48 hours: refuse.” Or a 60-hour snapshot returned with no warning.
                    
      
                    Why it fails
                    Nobody wrote a 48-hour rule, so the next run behaves differently and no test can be written. Hiding the age lets right meaning pass as fresh data.
                    
    
                    
    
                    For builders SQL
                    
      
                    The view stores facts; the caller supplies the clock. No now() in a view, so F00 and F01 can run on frozen clocks.
                    

                    SELECT view_name, warn_after_hours, hard_expiry_hours,   -- 36, NULL
       extract(epoch FROM (TIMESTAMPTZ '2026-07-01 09:00:00+00'
                           - data_loaded_at_utc)) / 3600 AS age_hours   -- 3
FROM analytics.data_status_by_view
WHERE view_name = 'analytics.mrr_summary_monthly';

                    Module 10 · Prove
                    
    
                    What do the tests prove, and what do they not?
                    
    
                    Say it in one lineTests check the setup, not the AI. Database checks and AI runs are two evidence planes; they never share a total, and any change invalidates both. The workshop ran 9 course tests; this builder's 70_checks.sql runs 22. Neither number grades the AI.
                    
    
                    
      
                    Which test catches this mistake?
                    
      
                    
      
                    
        
                    
          
                    Database plane: 70_checks.sql
                    
          
                      
          
                      DB CHECKS 22 of 22 PASS. 0 SKIP. 0 FAIL.
                      
          
                      Why 22, when the deck showed 9 of 9? They are not the same suite. The workshop ran 9 course tests: G01–G05, D01 and three policy cases (C01, R01, R02). A database cannot test a clarify or a refuse, so those three move to the AI run log. This builder's 70_checks.sql keeps G01–G05 and D01 and adds access (B-), reconciliation and lineage (Q-), teaching (T-) and freshness (F-) checks: 6 + 5 + 7 + 2 + 2 = 22. Neither number grades the AI. The quick start shows 21 of 21 and 1 SKIP until you log in as the reader: B-S01 needs the login's settings.
                      
        
                      
        
                      
          
                      AI plane: run log
                      An observation, not a benchmark
                      
          
                      WhenAI routeRunsValuesCited
                      
          
                      No total. One or two runs per case: observations.
                      
          
                      Values and Cited count only answer cases. A clarify or a refuse returns no value and cites no metric, so it counts as behaviour only. The deck graded the definition citation on the approved lane only.
                      
        
                      
      
                      
      
                      
      
                      
    
                      
    
                      
      
                      Good
                      “DB CHECKS 22 of 22 PASS. These test the database and course rules, not the AI.” AI runs logged separately, three per case.
                      
      
                      Counter-example
                      “The deck's 9 of 9 tests pass, so the AI scores 9 of 9.”
                      
      
                      Why it fails
                      The deck's 9 of 9 (22 checks in this builder) never asked the AI anything. The recorded approved-lane runs matched 3 of 3 values and cited the definition 0 of 3; an average would hide that gap.

                            Reference · Words
                            
    
                            Glossary
                            
    
                            Start with the first block if you have never written SQL. The words below it are for building.
                            
    
                            
      
                            MRR
                            Monthly recurring revenue: what accounts pay per month for their subscriptions. FOLDLINE's ending MRR at the end of June 2026 is €387,015. It is not revenue in the accounting sense, not cash and not profit.
                            
      
                            Level, change, rate
                            Three kinds of number. A level is measured at one moment (ending MRR, €387,015 on 30 June). A change is what flowed in or out during a period (net new MRR, +€42,565 in June). A rate is one count divided by another (logo churn, 4 of 40 = 10.0 %).
                            
      
                            Four blanks
                            The four things the AI had to guess in the workshop: Kind of number? Rows per what? Which months? Which table? For ending MRR: a level; one row per month; each complete month, never added; analytics.mrr_summary_monthly.
                            
      
                            Five boxes
                            The question card from the workshop: the question, the approved view, the four blanks, the boundary (what must be refused) and the test. They are the design order; the runbook in module 12 is the build order.
                            
      
                            Schema
                            A named folder of tables and views inside a database. FOLDLINE has source, core and analytics; the AI may look only in analytics.
                            
      
                            View
                            A saved query that looks like a table. analytics.mrr_summary_monthly is a view: it holds no copy of the data, it computes its rows from core each time it is read.
                            
      
                            Login and role
                            The name the AI uses to connect to the database. PostgreSQL calls it a role; a role that may connect is a login. FOLDLINE's AI connects as foldline_ready_reader.
                            
      
                            Grant
                            A permission given to a role: who may read what. foldline_ready_reader has SELECT on five views and nothing else. Everything not granted fails with SQLSTATE 42501, “permission denied”.
                            
      
                            Trace
                            The last part of an answer that says where it came from: metric name and version, view or file, period, unit, load time and data age. The recorded runs cited the definition 0 of 3; the trace is what makes that visible.
                            
      
                            Pooled rate
                            Total numerator ÷ total denominator. Churn for all segments: 12 of 120 = 10.0 %. Web shop: 480 orders of 21,000 sessions = 2.29 %, not the average of 2 % and 8 %.
                            
      
                            Pseudonymous key
                            A stand-in for an identity, such as fl_0006. It is not a name or an email, but it is stable and joinable, so it can be linked back. Pseudonymous is not anonymous.
                            
      
                            Guardrail
                            A check in your application, or a default setting, that the reader can bypass: a hook, a read-only default, a connector setting. It narrows mistakes, but it is not a lock. Guides and guardrails belong to the first lock (refuse early); only the database role is the second lock (enforce anyway).
                            
      
                            Semantic layer
                            The written layer between tables and readers: what each number means, which view answers it, what must be refused. In this kit: model.yml, metric.yml, policy.yml, verified-questions.yml.
                            
      
                            Additive
                            May be added along every axis. Changes such as net new MRR are additive.
                            
      
                            Semi-additive
                            May be added across things, never across time. Levels such as ending MRR are semi-additive.
                            
      
                            Non-additive
                            Never added. Rates, averages and distinct counts are recomputed from their parts.
                            
      
                            Grain
                            What one row stands for. “One row per account and month” and “one row per month” are different grains.
                            
      
                            Serving view
                            A view in analytics cut to one question family, with approved names, units, data-state columns and complete periods only.
                            
      
                            Allowlist
                            A list of what is allowed; everything else is denied. The reader may SELECT five named views. A denylist lets a new schema through the day it appears.
                            
      
                            MCP
                            Model Context Protocol: a standard way to connect an AI tool to a data source. A database connector over MCP logs in with whatever login you give it, so give it the read-only reader.
                            
      
                            Skill
                            A folder with a SKILL.md file that Claude loads when its description matches the task, for example .claude/skills/foldline-analytics/SKILL.md. It guides; it does not enforce.
                            
      
                            Hook
                            A command Claude Code runs at a fixed point, for example before a tool call. A hook can block a query that is not on the allowlist. It is a guardrail in your application, not a database lock.
                            
      
                            Evaluation clock
                            The stated “now” used to judge freshness and periods: 2026-07-01 09:00 UTC in the course. Tests use a frozen clock, never now().

                              •
